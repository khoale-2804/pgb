**pgb** is a two-stage [sqlc](https://sqlc.dev) process plugin that turns your Postgres schema into one Go package — `db/` — so the repetitive SQL layer never gets hand-written again. You keep your schema as plain SQL and keep sqlc for analysis and handwritten queries; pgb adds the layer sqlc deliberately doesn't provide, all under a single shared type map:

1. **Models** — typed structs, generated with sqlc-gen-go-compatible behavior.
2. **Stage 1: builders** — per-table column descriptors with typed predicates, including every ParadeDB pg_search operator on `paradedb`-indexed columns.
3. **Stage 2: static functions** — `Get / List / Count / Insert / InsertBatch / Update / Upsert / Delete / Search / HybridSearch` per table, ready to call.
4. **Query wrappers** — typed Go functions for the handwritten queries sqlc already resolved.

The whole flow, end to end — no SQL strings in application code:

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"os"
	"time"

	"github.com/jackc/pgx/v5/pgxpool"

	// handwritten runtime — small, versioned, readable
	pgb "github.com/your-org/pgb/core"

	// generated — one package, DO NOT EDIT
	"github.com/your-org/shop/db"
)

func main() {
	ctx := context.Background()

	// any pgx executor satisfies pgb.DBTX: pool, conn, or tx
	pool, err := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
	if err != nil {
		log.Fatal(err)
	}
	defer pool.Close()

	// insert — typed params, the full row comes back
	// INSERT INTO users (email, name) VALUES ($1, $2)
	// RETURNING id, email, name, bio, created_at
	ada, err := db.InsertUser(ctx, pool, db.InsertUserParams{
		Email: "ada@example.com", Name: "Ada Lovelace",
	})
	if err != nil {
		log.Fatal(err)
	}

	// dynamic list — filters compose structurally;
	// no (@x IS NULL OR col = @x)
	users, err := db.ListUsers(ctx, pool, db.UserFilter{
		EmailLike:    pgb.Opt("%@example.com"),
		CreatedAfter: pgb.Opt(time.Now().Add(-30 * 24 * time.Hour)),
	}, pgb.Limit(20))
	if err != nil {
		log.Fatal(err)
	}

	// search — generated from the USING paradedb index in your schema
	// WHERE description === $1::pdb.fuzzy(1)
	//   AND category ||| $2::pdb.boost(2)
	// ORDER BY pdb.score(id) DESC, id ASC   -- Top-K pushdown
	hits, err := db.SearchProducts(ctx, pool, "runing shoes",
		db.SearchOpts{
			Fuzzy:         1, // tolerates the typo
			BoostCategory: 2.0,
			Snippet:       "description", // pdb.snippet(...)
		})
	if err != nil {
		log.Fatal(err)
	}

	// single-row lookup with a typed sentinel
	_, err = db.GetUser(ctx, pool, ada.ID)
	switch {
	case errors.Is(err, pgb.ErrNotFound): // wraps pgx.ErrNoRows
		fmt.Println("user is gone")
	case err != nil:
		log.Fatal(err)
	default:
		fmt.Printf("%d users, %d hits, user exists\n",
			len(users), len(hits))
	}
}
```

## The problem it solves

Pure sqlc is static: every query is hand-written SQL. Dynamic filtering devolves into planner-hostile workarounds like `(@x IS NULL OR col = @x)` (a known [anti-pattern](https://github.com/sqlc-dev/sqlc/discussions/364)), and anything ParadeDB-flavored needs raw SQL escape hatches.

pgb keeps sqlc where it is strong — parsing your schema, analyzing your handwritten queries — and generates the runtime query builder, typed to your actual columns, plus static functions for the CRUD shapes every table repeats. Why one plugin and one package: [architecture overview](/architecture/overview).

## What gets generated

```text
db/
├── models.gen.go           # User, Product, params, filters, sets
├── users.gen.go            # predicates, builder, statics
├── products.gen.go         # same for products
└── products_search.gen.go  # SearchProducts (+ Page/Hybrid)
                            # for tables with a USING paradedb index
```

One package (config `package: db`), flat files, `// Code generated ... DO NOT EDIT.` headers — on top of a small handwritten `core/` runtime the generated code imports. See the [quickstart](/welcome/quickstart) for the full walkthrough.
