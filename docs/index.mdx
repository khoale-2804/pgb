The whole flow, end to end — no SQL strings in application code:

```go
package main

import (
    "context"
    "errors"
    "log"

    "github.com/khoale-2804/pgb/core"
    "github.com/jackc/pgx/v5/pgxpool"
    db "github.com/khoale-2804/shop/db"
)

func main() {
    ctx := context.Background()
    pool, err := pgxpool.New(ctx, "postgres://localhost/shop")
    if err != nil {
        log.Fatal(err)
    }

    // static layer: insert, read, update — no hand-written SQL
    u, err := db.InsertUser(ctx, pool, db.InsertUserParams{
        Email: "ada@example.com",
        Name:  "Ada",
    })
    if errors.Is(err, pgb.ErrNotFound) {
        log.Fatal("unreachable: insert always returns the row")
    }

    users, err := db.ListUsers(ctx, pool, db.UserFilter{
        EmailLike:    pgb.Opt("%@example.com"),
        CreatedAfter: pgb.Opt(u.CreatedAt),
    })

    // search layer: BM25 with fuzzy matching, scored, snippeted
    hits, err := db.SearchProducts(ctx, pool, "runing shoes", db.SearchOpts{
        Fuzzy:   1,
        Snippet: "description",
    })
    for _, h := range hits {
        log.Printf("%.2f  %s  %s", h.Score, h.Product.Title, h.Snippet["description"])
    }
}
```

## Why pgb exists

Hand-written SQL grows two failure modes: dynamic filters become
`(@x IS NULL OR col = @x)` — a [planner anti-pattern](https://github.com/sqlc-dev/sqlc/discussions/364) —
and extension features like [ParadeDB](/paradedb/overview) fall back to raw strings.
pgb compiles the layer sqlc deliberately doesn't provide, while sqlc keeps doing
what it is best at: analysis and vetting of the queries you *do* write by hand.
