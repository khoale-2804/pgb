Models are emitted by pgb itself (pass A), forked from sqlc-gen-go's behavior — same struct shapes, same familiar defaults — so that models, builder predicates, function params, and row scans all share **one type map**.

## Defaults

| Postgres | Go (default) | notes |
|---|---|---|
| `text` `varchar` `bpchar` `citext` `name` | `string` | |
| `boolean` | `bool` | |
| `int2` / `int4` / `int8` | `int16` / `int32` / `int64` | |
| `oid` | `uint32` | |
| `float4` / `float8` | `float32` / `float64` | |
| `numeric` | `pgtype.Numeric` | override to `json.Number` / `string` for money |
| `uuid` | `uuid.UUID` (google) | |
| `bytea` | `[]byte` | |
| `json` `jsonb` | `[]byte` | override to a typed struct or map |
| `timestamptz` `timestamp` | `pgtype.Timestamptz` | |
| `date` | `pgtype.Date` | |
| `interval` | `pgtype.Interval` | |
| `inet` `cidr` `macaddr` | `pgtype.*` | |
| range types | `pgtype.Range[T]` | |
| user-defined enum | generated string type | |
| `vector` (pgvector) | override → `pgvector.Vector` | required for hybrid search |
| unknown / `any` | `any` | untyped columns (e.g. `pdb.score()` under sqlc v1.31.1) |

## The generated struct

Take this `users` table — nullable text, jsonb, array, and nullable timestamp columns all in one:

```sql
CREATE TABLE users (
    id            bigserial PRIMARY KEY,
    email         text        NOT NULL UNIQUE,
    name          text        NOT NULL,
    bio           text,
    metadata      jsonb,
    tags          text[],
    created_at    timestamptz NOT NULL DEFAULT now(),
    last_login_at timestamptz
);
```

pgb emits into `db/models.gen.go`:

```go
// Code generated by pgb. DO NOT EDIT.
package db

import (
    "github.com/jackc/pgx/v5/pgtype"
)

type User struct {
    ID          int64
    Email       string
    Name        string
    Bio         pgtype.Text        // nullable text
    Metadata    []byte             // jsonb — raw bytes unless overridden
    Tags        []string           // text[] — decoded natively by pgx
    CreatedAt   pgtype.Timestamptz // NOT NULL, but the timestamp family still maps to pgtype
    LastLoginAt pgtype.Timestamptz // nullable — Valid == false means SQL NULL
}
```

Where the interesting columns land:

| column | Go field | SQL NULL is |
|---|---|---|
| `bio` | `pgtype.Text` | `Valid: false` |
| `metadata` | `[]byte` | `nil` |
| `tags` | `[]string` | `nil` |
| `last_login_at` | `pgtype.Timestamptz` | `Valid: false` |

With the `nullability: pointers` option the same table scans into `*string` for `bio`, `*[]byte` for `metadata`, and `*pgtype.Timestamptz` for `last_login_at` — every nullable column becomes a pointer; non-nullable columns never change.

## The matching scan function

Every model gets a generated, explicit-position scan function — no reflection:

```go
// Code generated by pgb. DO NOT EDIT.

func scanUser(row pgx.Row) (User, error) {
    var u User
    err := row.Scan(
        &u.ID,
        &u.Email,
        &u.Name,
        &u.Bio,
        &u.Metadata,
        &u.Tags,
        &u.CreatedAt,
        &u.LastLoginAt,
    )
    return u, err
}
```

Three properties worth knowing:

- The scan order is the exact order of the explicit column list every generated `SELECT` emits. There is no `SELECT *` anywhere in pgb, so `ALTER TABLE ... ADD COLUMN` cannot shift scan positions.
- `pgtype` values implement pgx's codec interfaces, so `Scan` decodes timestamps, arrays, ranges, and JSON without glue code.
- The function is per-model and shared: `GetUser`, `ListUsers`, and the builders' `All` all scan through it — one definition, one type map.

## pgtype in practice

Writing a timestamp (and clearing it back to NULL) through the three-state `Set` type:

```go
u, err := db.UpdateUser(ctx, pool, u.ID, db.UserSet{
    LastLoginAt: pgb.Set(pgtype.Timestamptz{Time: time.Now(), Valid: true}),
})
```

```sql
UPDATE public.users
SET last_login_at = $1
WHERE id = $2
RETURNING id, email, name, bio, metadata, tags, created_at, last_login_at
```

```go
_, err = db.UpdateUser(ctx, pool, u.ID, db.UserSet{
    LastLoginAt: pgb.Null[pgtype.Timestamptz](),   // SET last_login_at = NULL
})
```

Reading `pgtype` values back is a `Valid` check plus the underlying field:

```go
u, err := db.GetUser(ctx, pool, 42)
if errors.Is(err, pgb.ErrNotFound) {
    return err
}

if u.LastLoginAt.Valid {
    fmt.Println("last seen", u.LastLoginAt.Time.UTC().Format(time.RFC3339))
}
if u.Bio.Valid {
    fmt.Println("bio:", u.Bio.String)
}
```

jsonb columns scan as raw `[]byte` by default — marshal on the way in, unmarshal on the way out:

```go
raw, err := json.Marshal(map[string]any{"plan": "pro", "seats": 12})
if err != nil {
    return err
}
_, err = db.UpdateUser(ctx, pool, u.ID, db.UserSet{
    Metadata: pgb.Set(raw),   // []byte → jsonb
})
```

```sql
UPDATE public.users
SET metadata = $1
WHERE id = $2
RETURNING id, email, name, bio, metadata, tags, created_at, last_login_at
```

```go
if len(u.Metadata) > 0 {
    var prefs map[string]any
    if err := json.Unmarshal(u.Metadata, &prefs); err != nil {
        return err
    }
    fmt.Println(prefs["plan"])
}
```

<Tip>
An override (`pgb:type=map[string]any` or the config equivalent) makes pgx's json codec scan the column straight into the typed value — the manual `json.Marshal`/`Unmarshal` round-trip disappears, and the same type shows up in params, filters, and scans (see [one map, every surface](#one-map-every-surface)).
</Tip>

## Three-state writes

For `UPDATE`/`INSERT` you need three states: *write value*, *write NULL*, *skip column*. pgb uses one generic instead of pointer tricks:

```go
package core

type Set[T any] struct {
    V       T
    IsNull  bool
    Defined bool
}

func Set[T any](v T) Set[T]  // write value
func Null[T any]() Set[T]    // write NULL
// zero value              // skip this column
```

```go
db.UpdateUser(ctx, pool, id, db.UserSet{
    Email: pgb.Set("new@corp.io"),   // SET email = $2
    Bio:   pgb.Null[string](),       // SET bio = NULL
    // CreatedAt: zero               // left untouched
})
```

## One map, every surface

Per-column Go types come from either the [config `overrides` list](/reference/config) or the [`pgb:type=` directive](/architecture/schema-ir):

```sql
COMMENT ON COLUMN users.metadata IS 'pgb:type=map[string]any';
```

```yaml
# equivalent config form
overrides:
  - column: public.users.metadata
    go_type: map[string]any
```

Because there is exactly one type map, that single override changes **all three usages at once** — the model field, the write params, and the scan target are regenerated together:

| surface | default (`jsonb` → `[]byte`) | after override → `map[string]any` |
|---|---|---|
| `db.User.Metadata` (model + scan target) | `[]byte` | `map[string]any` |
| `db.InsertUserParams.Metadata` | `[]byte` | `map[string]any` |
| `db.UserSet.Metadata` | `core.Set[[]byte]` | `core.Set[map[string]any]` |

The drift this eliminates is the classic two-generator failure mode — models and query code produced from two independent type maps:

```go
// two maps, two truths — what pgb makes impossible:
type User struct {
    Metadata []byte         // generator 1 said: jsonb → []byte
}

type UserFilter struct {
    Metadata map[string]any // generator 2 said: jsonb → map[string]any
}

// every call site now needs a hand-rolled conversion, and nothing
// checks either declaration against the actual database
```

With pgb, pass A generates the models and the scan/param code *from the same map*, assigning into the same structs — if the mapping ever disagreed with itself, the build breaks at `go build`, never as a silent mis-scan at runtime.

Columns typed `any` (unresolved extension functions in handwritten queries on sqlc v1.31.1) surface as explicit `any` fields — the nudge is to cast in SQL (`pdb.score(id)::float8`) for a clean type.
