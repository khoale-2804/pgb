## Prerequisites

| requirement | version | why |
|---|---|---|
| Go | 1.24+ | generated code uses generics and pgx/v5 |
| PostgreSQL | 15, 16, 17, 18 | 19 is a gated beta target — see the [support matrix](/reference/support-matrix) |
| sqlc | v1.31.1 or `@main` | plugin edition only |
| ParadeDB pg_search | 0.25.9+ / 0.26-rc | only for search features — plain Postgres works for CRUD |

## 1. Install sqlc (plugin edition)

The PostgreSQL 18 parser (`sqlc-dev/oliphant`) and unknown-function tolerance
are merged on sqlc **main** but not yet in a tagged release (latest:
v1.31.1, 2026-04-22):

```bash
go install github.com/sqlc-dev/sqlc/cmd/sqlc@main
sqlc version   # reports v1.31.1 even on main — the binary is the main build
```

## 2. Install pgb

```bash
# plugin binary (edition A)
go install github.com/khoale-2804/pgb/cmd/sqlc-gen-pgb@latest

# standalone CLI (edition B)
go install github.com/khoale-2804/pgb/cmd/pgb@latest
```

Both read the same schema; see [Editions](/editions/overview) for the
difference.

## 3. A database with pg_search

For search features you need the ParadeDB extension — the fastest way is
their Docker image, which also bundles pgvector. Pin the tag: pgb emits
`USING paradedb` index DDL, and that access method only exists on
pg_search 0.25+ (0.24 and earlier create indexes with `USING bm25`):

```bash
docker run -d --name pgb-demo -e POSTGRES_PASSWORD=postgres \
  -p 5432:5432 paradedb/paradedb:0.25.9
```

`0.25.9` is the version pgb's own integration lane tests against — the
tested floor. `CREATE EXTENSION pg_search;` and `CREATE EXTENSION
vector;` in that database, then point your connection string at it.
Plain `postgres:18` works for everything non-search.

## 4. Verify

From the [quickstart fixture](/welcome/quickstart):

```bash
sqlc generate    # edition A: emits db/ without errors
```

If `sqlc generate` complains about `pdb.*` functions in handwritten
queries, you are on v1.31.1 — switch to `@main` (see the
[support matrix](/reference/support-matrix) for what each version buys).
